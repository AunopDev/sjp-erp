# ทำงานประหยัด token และใช้ได้กับทุกโมเดล

ใช้กับทุกงาน token ที่เสียไปกับการอ่านของที่ไม่เกี่ยวและผลลัพธ์คำสั่งที่ยาวเกิน ทำให้งานช้า แพง และทำให้โมเดลหลุดจากประเด็น เป้าหมายคืออ่านและพิมพ์เท่าที่งานต้องใช้ โดยไม่ลดการตรวจสอบ

การประหยัดห้ามแลกกับความถูกต้อง: ยังต้องอ่านไฟล์ที่จะแก้ ยังต้องรัน typecheck และ test และยังต้องตรวจก่อนอ้าง

## หลักการ

1. **ค้นก่อนอ่าน:** หาตำแหน่งด้วยการค้น แล้วอ่านเฉพาะช่วงที่เกี่ยว
2. **จำกัดผลลัพธ์ทุกคำสั่ง:** ผลลัพธ์ที่ยาวเกินร้อยบรรทัดแทบไม่เคยจำเป็นทั้งหมด
3. **ไม่ทำซ้ำ:** ไม่อ่านไฟล์เดิมซ้ำถ้าไม่ได้เปลี่ยน ไม่รันคำสั่งเดิมซ้ำเพื่อดูผลเดิม
4. **รวมงานที่ไม่ขึ้นต่อกัน:** คำสั่งที่ไม่ต้องรอผลของกันให้ส่งพร้อมกันในรอบเดียว
5. **ตอบสั้นเท่าที่ครบ:** ไม่เล่าขั้นตอนที่ทำ ไม่ทวนคำถาม ไม่พิมพ์ไฟล์ทั้งไฟล์กลับไปถ้าแก้ไม่กี่บรรทัด

## คำสั่งที่ประหยัด

ใช้เครื่องมือค้นและอ่านไฟล์ของ session ถ้ามี เพราะมักจำกัดผลลัพธ์ให้อยู่แล้ว ถ้าต้องใช้ shell ให้ใช้รูปแบบเหล่านี้

| ต้องการ                               | เปลือง                              | ประหยัด                                                                                       |
| ------------------------------------- | ----------------------------------- | --------------------------------------------------------------------------------------------- |
| ดูโครงสร้างโปรเจ็กต์                  | `ls -R` หรือ `find .` ทั้งโปรเจ็กต์ | `git ls-files \| head -200` หรือแสดงโฟลเดอร์ลึก 2 ชั้น โดยข้าม `node_modules`, `dist`, `.git` |
| หาว่าของอยู่ไฟล์ไหน                   | เปิดอ่านทีละไฟล์                    | ค้นให้แสดงเฉพาะชื่อไฟล์: `grep -rl "ชื่อ" src` หรือ `rg -l "ชื่อ" src`                        |
| ดูการใช้งานของฟังก์ชัน                | อ่านทั้งไฟล์                        | ค้นพร้อมเลขบรรทัดและจำกัดจำนวน: `grep -rn "ชื่อ(" src \| head -30`                            |
| อ่านส่วนหนึ่งของไฟล์ใหญ่              | อ่านทั้งไฟล์                        | อ่านช่วงบรรทัดที่ต้องการ: `sed -n '120,180p' ไฟล์`                                            |
| ดูว่าเปลี่ยนอะไรไป                    | `git diff` ทั้งหมดทุกครั้ง          | `git diff --stat` ก่อน แล้ว `git diff -- <ไฟล์>` เฉพาะที่ต้องดู                               |
| ดูประวัติ                             | `git log`                           | `git log --oneline -15`                                                                       |
| รัน test                              | ทั้งชุดทุกครั้ง แสดงผลเต็ม          | ระหว่างทำ: เฉพาะไฟล์ที่เกี่ยว ก่อนส่ง: ทั้งชุดหนึ่งครั้ง                                      |
| ผลลัพธ์ของ build หรือ test ที่ยาว     | แสดงทั้งหมด                         | ดูส่วนท้ายและบรรทัดที่ผิด: `<คำสั่ง> 2>&1 \| tail -40`                                        |
| ติดตั้งหรือ build                     | แสดงความคืบหน้าทั้งหมด              | ใช้ตัวเลือกเงียบของเครื่องมือ หรือดูเฉพาะส่วนท้าย                                             |
| ดูไฟล์ข้อมูลขนาดใหญ่ (JSON, CSV, log) | เปิดทั้งไฟล์                        | ดูขนาดก่อน (`wc -l`) แล้วดูหัว ท้าย หรือกรองเฉพาะส่วน                                         |

ข้อควรระวัง:

- อย่าตัดผลลัพธ์จนพลาดข้อผิดพลาด ถ้าคำสั่งล้มเหลวและส่วนท้ายไม่พอ ให้ค้นหาคำว่า error ในผลลัพธ์ หรือขยายช่วงที่ดู
- ไม่อ่าน `node_modules`, โฟลเดอร์ build, ไฟล์ lock, ไฟล์ที่ย่อแล้ว เว้นแต่งานคือเรื่องนั้นโดยตรง
- ก่อนแก้ไฟล์ ต้องอ่านส่วนที่จะแก้และบริเวณรอบ ๆ จริง การประหยัดไม่ใช่เหตุผลให้แก้โดยไม่อ่าน

## การแก้ไฟล์

- แก้เฉพาะจุดด้วยเครื่องมือแก้ไขแบบแทนที่ข้อความ ไม่เขียนทับทั้งไฟล์เพื่อเปลี่ยนไม่กี่บรรทัด
- ไม่พิมพ์เนื้อหาไฟล์ซ้ำจากความจำหรือจากผลลัพธ์ที่อาจถูกตัด
- แก้หลายจุดในไฟล์เดียวให้ทำต่อเนื่อง แล้วตรวจครั้งเดียว
- หลังแก้ไม่ต้องอ่านไฟล์ซ้ำเพื่อยืนยัน ให้ยืนยันด้วย typecheck หรือ test

## การอ่านสกิลนี้

- อ่าน `SKILL.md` แล้วอ่านเฉพาะไฟล์อ้างอิงที่ตารางระบุสำหรับชนิดงานนั้น ไม่อ่านทุกไฟล์
- ไฟล์ที่มีสารบัญ ให้ไปหัวข้อที่ต้องใช้
- อ่านไฟล์อ้างอิงไปแล้วใน session เดียวกัน ไม่ต้องอ่านซ้ำ
- ใช้สคริปต์ใน `scripts/` แทนการไล่ตรวจด้วยตาในเรื่องที่สคริปต์ตรวจได้

## รูปแบบคำตอบ

- ขึ้นต้นด้วยผลลัพธ์ ไม่มีคำนำ
- โค้ดที่แก้ให้อ้างชื่อไฟล์และสรุปสิ่งที่เปลี่ยน ไม่วางไฟล์ทั้งไฟล์ เว้นแต่เจ้าของขอ
- ใช้ตารางและรายการเมื่อช่วยให้อ่านเร็วขึ้น ไม่ใช้เพื่อให้ดูเป็นทางการ
- ไม่ย่อจนผู้อ่านต้องเดา: ใช้ประโยคเต็ม ระบุชื่อไฟล์และคำสั่งให้ครบ
- งานยาวให้สรุปสถานะเป็นระยะแบบสั้น ๆ: ทำอะไรเสร็จ เหลืออะไร ติดอะไร

## ใช้กับโมเดลและเอเจนต์ใดก็ได้

สกิลนี้เป็นไฟล์ markdown และสคริปต์ Node ธรรมดา ไม่ผูกกับเครื่องมือของค่ายใด

- **คำสั่งในสกิลเขียนเป็นการกระทำ** เช่น "ค้นหา", "อ่านไฟล์", "รันคำสั่ง" ให้ใช้เครื่องมือที่ session มี ถ้าไม่มีเครื่องมือสำหรับขั้นใด ให้ทำเท่าที่ทำได้และระบุในรายงานว่าขั้นใดไม่ได้ทำ
- **ไม่มี shell:** ข้ามการรันสคริปต์และคำสั่งตรวจ ตรวจด้วยมือตามกฎเดียวกัน และบอกเจ้าของว่าต้องรันคำสั่งใดเอง
- **ไม่มีเครื่องมือถามแบบตัวเลือก:** ถามเป็นข้อความตามรูปแบบใน [requirements.md](requirements.md)
- **ไม่มีเอเจนต์ย่อย:** ทำเองตามลำดับ
- **หน้าต่าง context เล็ก:** อ่านทีละไฟล์อ้างอิง จดสิ่งที่ต้องใช้เป็นบันทึกสั้น ๆ ก่อนอ่านไฟล์ถัดไป
- **โมเดลเล็ก:** ทำตามตารางขั้นตอนทีละขั้น เขียนแบบฟอร์มใน [thinking.md](thinking.md) ออกมาจริง และใช้ตัวอย่างใน [worked-example.md](worked-example.md) เป็นแบบ

วิธีให้เอเจนต์ที่ไม่รู้จักระบบสกิลใช้สกิลนี้: ใส่ข้อความนี้ในไฟล์คำสั่งของโปรเจ็กต์ (เช่น `AGENTS.md`) โดยแทน path ให้ตรงกับเครื่อง

```text
ก่อนทำงานเกี่ยวกับโค้ด flow ระบบ หรือหน้าจอ ให้อ่าน <path>/aunop-dev-skill/SKILL.md
แล้วทำตามขั้นตอนในนั้น อ่านไฟล์ใน references/ เฉพาะที่ SKILL.md ระบุสำหรับชนิดงานนั้น
และรันสคริปต์ใน scripts/ ก่อนส่งงาน
```

- [ ] ไม่ได้อ่านไฟล์เดิมหรือรันคำสั่งเดิมซ้ำโดยไม่จำเป็น
