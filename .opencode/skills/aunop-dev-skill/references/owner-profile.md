# ข้อมูลและความชอบของเจ้าของ

คำตอบที่เจ้าของให้ไว้ ใช้เป็นค่าตั้งต้นของทุกโปรเจ็กต์ ไฟล์นี้มีน้ำหนักเหนือค่าตั้งต้นทั่วไปในไฟล์อ้างอิงอื่น แต่ต่ำกว่าคำสั่งล่าสุดของเจ้าของและ AGENTS.md ของโปรเจ็กต์ เมื่อเจ้าของบอกความชอบใหม่ที่ใช้กับทุกโปรเจ็กต์ ให้เสนอเพิ่มในไฟล์นี้

## ตัดสินใจแล้ว

| เรื่อง | ค่าที่ใช้ |
| --- | --- |
| ชื่อตาราง | ลงท้าย `_tb` เช่น `user_tb` |
| ชื่อคอลัมน์ | ขึ้นต้นด้วยชื่อข้อมูลของตาราง: `test_id`, `test_name` |
| คอลัมน์วันที่ | `<ชื่อ>_create_date`, `<ชื่อ>_update_date` ทุกตาราง |
| โครงสร้างไฟล์ | จัดตามฟีเจอร์ แนว Angular และ NestJS ตาม [project-structure.md](project-structure.md) |
| วันที่บนหน้าจอ | ตัวเลขล้วน วัน/เดือน/ปี ภาษาไทยใช้ปี พ.ศ. เช่น `13/11/2569` ภาษาอังกฤษใช้ปี ค.ศ. เช่น `13/11/2026` |
| ภาษาบนหน้าจอ | สองภาษา ไทยและอังกฤษ สลับได้ |
| คอมเมนต์ในโค้ด | ภาษาไทย |
| ข้อความ commit และ pull request | ภาษาอังกฤษ |
| ชื่อตัวแปร ฟังก์ชัน ไฟล์ | ภาษาอังกฤษ |
| การถามกลับ | ไม่เข้าใจหรือตีความได้หลายทางให้ถามก่อน ตาม [requirements.md](requirements.md) |

## ต้องถามเจ้าของทุกโปรเจ็กต์

เจ้าของไม่มีค่าตั้งต้นสำหรับเรื่องเหล่านี้ ห้ามเลือกเอง ให้ถามเมื่อเริ่มโปรเจ็กต์ใหม่หรือเมื่องานมาถึงจุดที่ต้องใช้ ถ้าโปรเจ็กต์มีอยู่แล้วให้อ่านจากโปรเจ็กต์แทนการถาม

| เรื่อง | ถามเมื่อ | วิธีเสนอ |
| --- | --- | --- |
| Tech stack (frontend, backend) | เริ่มโปรเจ็กต์ใหม่ | เสนอ 2–3 ชุดตาม [tech-stack.md](tech-stack.md) |
| ฐานข้อมูล | เริ่มโปรเจ็กต์ใหม่ หรือก่อนเขียน SQL และ migration ชุดแรก | เสนอพร้อมเหตุผล และใช้ไวยากรณ์ของตัวที่เลือก |
| สี ฟอนต์ และแนวหน้าตา | ก่อนออกแบบหน้าจอแรกของโปรเจ็กต์ | ถามสีหลักและแนวที่ต้องการ ระหว่างรอใช้ token กลางใน [ui-patterns.md](ui-patterns.md) และระบุว่าเป็นค่าชั่วคราว |
| ที่รันระบบ | ก่อนเตรียม deploy | ถามว่ารันที่ไหนและมีข้อจำกัดอะไร |

## กฎที่ตามมาจากคำตอบ

### วันที่

- เก็บในฐานข้อมูลเป็นเวลามาตรฐาน (ค.ศ., UTC สำหรับเวลาที่เกิดเหตุการณ์) แปลงเป็น พ.ศ. เฉพาะตอนแสดงผล
- รูปแบบแสดงผล: `dd/MM/yyyy` ทั้งสองภาษา ลำดับวัน/เดือน/ปีเหมือนกัน ต่างกันที่ปี: หน้าจอภาษาไทยใช้ พ.ศ. (ค.ศ. + 543) หน้าจอภาษาอังกฤษใช้ ค.ศ. มีเวลาด้วยให้เป็น `13/11/2569 14:30` หรือ `13/11/2026 14:30` แบบ 24 ชั่วโมง
- การแปลงทำที่ฟังก์ชันหรือ pipe กลางตัวเดียวที่รับภาษาปัจจุบันเป็นตัวกำหนดปี ไม่บวก 543 กระจายตามหน้าจอ และห้ามบันทึกปี พ.ศ. ลงฐานข้อมูล
- ช่องกรอกวันที่แสดงและรับค่าตามปีของภาษาที่แสดงอยู่ สลับภาษาแล้ววันที่ที่กรอกไว้ต้องยังเป็นวันเดียวกัน ทดสอบวันที่ 29 กุมภาพันธ์ ช่วงข้ามปี และการสลับภาษากลางฟอร์ม

### สองภาษา

- ข้อความทุกชิ้นที่ผู้ใช้เห็นอยู่ในไฟล์คำแปลแยกภาษา (`th`, `en`) อ้างด้วย key ห้ามเขียนข้อความลงใน component, template หรือโค้ด backend โดยตรง
- ใช้กลไกแปลภาษาที่โปรเจ็กต์มี ถ้ายังไม่มีให้เสนอทางเลือกและถามเจ้าของก่อนเพิ่ม package
- key ตั้งตามตำแหน่งและความหมาย เช่น `leave.list.empty_title` ไม่ตั้งตามข้อความ
- เพิ่มหรือแก้ข้อความต้องทำครบทั้งสองภาษาในงานเดียวกัน ภาษาไทยเป็นต้นฉบับ
- backend ส่ง `code` ของ error ให้ frontend เลือกข้อความตามภาษา ไม่พึ่งข้อความจาก server เป็นข้อความที่แสดง
- ออกแบบหน้าจอให้รับข้อความที่ยาวต่างกันระหว่างสองภาษา ไม่กำหนดความกว้างปุ่มหรือป้ายตายตัว และตรวจทั้งสองภาษา
- มีตัวสลับภาษาที่เห็นได้จากทุกหน้า จำค่าที่เลือก และตั้ง `lang` ของหน้าให้ตรงกับภาษาที่แสดง
- ข้อมูลที่ผู้ใช้กรอกเองไม่แปล

### ภาษาในโค้ดและ git

- คอมเมนต์เขียนไทย อธิบายเหตุผลของ logic ไม่บรรยายสิ่งที่โค้ดบอกอยู่แล้ว
- ข้อความ commit หัวข้อและเนื้อหา pull request เขียนอังกฤษ ตามรูปแบบใน [git-workflow.md](git-workflow.md)
- รายงานถึงเจ้าของเขียนภาษาเดียวกับที่เจ้าของใช้สั่งงาน
