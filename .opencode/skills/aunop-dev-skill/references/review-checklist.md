# Checklist ก่อนส่งมอบ

ใช้เฉพาะหมวดและข้อที่เกี่ยวข้อง ถ้าไม่เกี่ยวให้ระบุเหตุผลสั้น ๆ ห้ามทำเครื่องหมายผ่านโดยไม่มีหลักฐาน

## ทุกงาน

- [ ] รันสคริปต์ตรวจใน `scripts/` ที่ตรงกับชนิดผลงาน ไม่มี `[error]` เหลือ และใส่ผลจริงในรายงาน
- [ ] ผลงานตรง scope และ acceptance criteria ไม่เกินและไม่ขาด
- [ ] การตัดสินใจที่ย้อนยากมีเหตุผลและทางเลือกที่พิจารณาแล้ว
- [ ] คิดเส้นทางผิดพลาดแล้ว ไม่ใช่เฉพาะเส้นทางสำเร็จ
- [ ] แยกสิ่งที่ตรวจแล้ว สมมติฐาน และคำถามค้างไว้ชัดเจน
- [ ] ไม่เพิ่ม dependency หรือแก้ไฟล์นอก scope โดยพลการ

## โค้ด

- [ ] ไม่มี `any`, unsafe cast หรือ placeholder ในโค้ดที่เพิ่ม/แก้
- [ ] ข้อมูลมี Zod schema และ type มาจาก schema โดยไม่ซ้ำซ้อน
- [ ] Validate request, database result และ input ภายนอกก่อนใช้
- [ ] Business logic แยกจาก framework/driver และ data access อยู่ใน repository
- [ ] ค่าธุรกิจ/config รวมศูนย์และชื่อฐานข้อมูลตรงข้อกำหนด
- [ ] Error มีผู้รับผิดชอบและถูกส่งไปตัวจัดการกลาง ไม่มี secret ใน log/response
- [ ] ตรวจ auth, injection, XSS และขอบเขตข้อมูลที่เปิดเผย
- [ ] งานเขียนข้อมูลส่งซ้ำได้อย่างปลอดภัย และป้องกัน concurrent request
- [ ] Promise มีผู้รับผิดชอบ ไม่มี unhandled rejection
- [ ] รองรับ metrics/trace ID ตามระบบเดิม
- [ ] Query มี pagination/index ตามความจำเป็นและไม่เกิด N+1
- [ ] พฤติกรรมสำคัญและ error path มีการตรวจที่เหมาะสม
- [ ] รัน typecheck/lint/test ที่เกี่ยวข้องด้วยคำสั่งของโปรเจ็กต์ และบันทึกผลจริง
- [ ] API spec และแผน compatibility/migration ถูกปรับเมื่อเกี่ยวข้อง
- [ ] งานที่มี endpoint ตาราง สิทธิ์ firmware หรือ commit ได้ตรวจตามรายการท้ายไฟล์ของหัวข้อนั้นแล้ว ([api-design.md](api-design.md), [database-design.md](database-design.md), [security.md](security.md), [iot-esp32.md](iot-esp32.md), [git-workflow.md](git-workflow.md))

## Flow และกระบวนการ

- [ ] ระบุ trigger, actor, ผลลัพธ์สุดท้าย และสิ่งที่อยู่นอกขอบเขต
- [ ] ทุกจุดตัดสินใจมีเงื่อนไขที่ตรวจได้ และทุกเส้นออกมีป้ายกำกับ
- [ ] มีเส้นทางสำหรับข้อมูลผิด ไม่มีสิทธิ์ ระบบภายนอกล้ม ส่งซ้ำ และยกเลิกกลางทาง
- [ ] ทุกสถานะที่ไม่ใช่สถานะสุดท้ายมีทางออก ไม่มีสถานะที่เข้าไม่ถึง
- [ ] ทุกขั้นมีผู้รับผิดชอบ และระบุข้อมูลที่อ่าน/เขียน
- [ ] ไล่ตัวอย่างจริงตามแผนภาพแล้ว ทั้งกรณีปกติและกรณีผิดพลาด
- [ ] Mermaid render ได้ และรูปหนึ่งตอบคำถามเดียว

## โครงสร้างและเครื่องมือ

- [ ] ชื่อตารางและคอลัมน์ตรงกฎ: `_tb`, `<ชื่อ>_id`, `<ชื่อ>_create_date`, `<ชื่อ>_update_date`
- [ ] ไฟล์ใหม่อยู่ตามโครงสร้างใน [project-structure.md](project-structure.md) หรือตามรูปแบบเดิมของโปรเจ็กต์
- [ ] การเลือก stack หรือ library ใหม่ได้เสนอเจ้าของตาม [tech-stack.md](tech-stack.md) และได้รับการยืนยันแล้ว
- [ ] จุดที่ไม่เข้าใจได้ถามเจ้าของแล้ว และสมมติฐานที่เหลือระบุไว้ในรายงาน
