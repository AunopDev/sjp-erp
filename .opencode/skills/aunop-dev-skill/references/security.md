# ความปลอดภัย

ใช้เมื่องานแตะข้อมูลผู้ใช้ การเข้าสู่ระบบ สิทธิ์ ไฟล์อัปโหลด ความลับ หรือรับข้อมูลจากภายนอก ขยายจากกฎข้อ 11 ใน [coding-standards.md](coding-standards.md) ใช้เป็นรายการตรวจตอนออกแบบและตอนรีวิว

ทำตามกลไกความปลอดภัยที่โปรเจ็กต์มีอยู่ ห้ามเขียนการเข้ารหัส การ hash รหัสผ่าน หรือระบบ session ขึ้นเอง ถ้าโปรเจ็กต์ยังไม่มีและงานต้องใช้ ให้ถามเจ้าของว่าจะใช้ library ใด

## คำถามที่ต้องตอบสำหรับทุกทางเข้า

ทางเข้าคือทุกจุดที่ข้อมูลจากภายนอกเข้ามา: endpoint, webhook, ข้อความจากอุปกรณ์, ไฟล์ที่อัปโหลด, งานตามเวลา

1. **ใครเรียก:** ยืนยันตัวตนอย่างไร ถ้าไม่ต้องยืนยัน เพราะอะไร
2. **มีสิทธิ์ทำสิ่งนี้หรือไม่:** role อะไรทำได้
3. **มีสิทธิ์กับข้อมูลชิ้นนี้หรือไม่:** เป็นเจ้าของหรืออยู่ในกลุ่มที่เข้าถึงได้หรือไม่
4. **ข้อมูลที่ส่งมาเชื่อได้แค่ไหน:** ผ่าน schema และมีขีดจำกัดขนาดหรือไม่
5. **ส่งอะไรกลับ:** มีฟิลด์ที่ผู้เรียกไม่ควรเห็นหรือไม่
6. **ถ้าถูกเรียกถี่ ๆ หรือซ้ำ ๆ:** เกิดอะไรขึ้น

ข้อ 3 เป็นข้อที่ถูกลืมบ่อยที่สุด การเข้าสู่ระบบแล้วไม่ได้แปลว่าเข้าถึงข้อมูลของทุกคนได้

## รายการตรวจตามหัวข้อ

### ตัวตนและสิทธิ์

- [ ] ตรวจสิทธิ์ที่ server ทุกครั้ง การซ่อนปุ่มในหน้าจอไม่ใช่การป้องกัน
- [ ] ทุก query ที่ดึงด้วย id มีเงื่อนไขเจ้าของหรือขอบเขตของผู้เรียก หรือมีการตรวจหลังดึง
- [ ] id ของผู้ใช้มาจาก session หรือ token ที่ตรวจแล้ว ไม่รับจาก body หรือ query
- [ ] role และสิทธิ์อ่านจากฝั่ง server ไม่เชื่อค่าที่ client ส่งมา
- [ ] ข้อมูลของคนอื่นตอบ 404 เมื่อไม่ควรเปิดเผยว่ามีอยู่

### ข้อมูลเข้า

- [ ] ทุก input ผ่าน schema ที่ระบุชนิด ความยาวสูงสุด ช่วงค่า และรูปแบบ
- [ ] ฟิลด์ที่ไม่รู้จักถูกตัดทิ้งหรือปฏิเสธ ไม่ส่งต่อทั้งก้อนเข้าฐานข้อมูล (กันการแก้ฟิลด์ที่ไม่ได้ตั้งใจเปิด เช่น `user_role`)
- [ ] SQL ใช้ parameter ทั้งหมด ชื่อคอลัมน์สำหรับเรียงหรือกรองเลือกจากรายการอนุญาต
- [ ] ไม่นำ input ไปประกอบคำสั่ง shell, path ของไฟล์, หรือ URL ที่ server จะเรียก โดยไม่ตรวจกับรายการอนุญาต
- [ ] มีขีดจำกัดขนาด body และจำนวนรายการใน array

### ข้อมูลออก

- [ ] response ผ่าน schema ที่เลือกฟิลด์ ไม่มี password hash, token, คีย์ภายใน
- [ ] ข้อความ error ไม่มี stack trace, SQL, path ของไฟล์ หรือชื่อระบบภายใน
- [ ] ข้อความจากผู้ใช้ที่แสดงบนหน้าเว็บถูก escape ตามบริบท ใช้กลไกของ framework ไม่แทรก HTML ดิบ
- [ ] ข้อความล็อกอินผิดไม่บอกว่าอีเมลนี้มีบัญชีหรือไม่

### รหัสผ่าน session และ token

- [ ] รหัสผ่านเก็บเป็น hash ด้วยอัลกอริทึมสำหรับรหัสผ่านโดยเฉพาะ ผ่าน library ที่โปรเจ็กต์ใช้
- [ ] token สุ่มจากตัวสร้างเลขสุ่มที่ปลอดภัยของระบบ มีวันหมดอายุ และยกเลิกได้
- [ ] cookie ของ session ตั้ง `HttpOnly`, `Secure`, `SameSite`
- [ ] การกระทำที่เปลี่ยนข้อมูลผ่าน cookie มีการป้องกัน CSRF ตามที่ framework ให้มา
- [ ] ลิงก์รีเซ็ตรหัสผ่านใช้ได้ครั้งเดียวและหมดอายุเร็ว
- [ ] จำกัดจำนวนครั้งของการล็อกอิน การขอรีเซ็ต และการส่ง OTP

### ความลับ

- [ ] ความลับ (คีย์ API, รหัสฐานข้อมูล, คีย์เซ็น token) อ่านจาก environment หรือที่เก็บความลับ ไม่อยู่ในโค้ด
- [ ] ไฟล์ที่มีความลับอยู่ใน `.gitignore` และมีไฟล์ตัวอย่างที่ไม่มีค่าจริง
- [ ] ไม่ log ความลับ, token, รหัสผ่าน, เลขบัตร หรือ body ทั้งก้อนของคำขอที่มีข้อมูลเหล่านี้
- [ ] ความลับไม่ถูกส่งไปฝั่ง client หรือฝังใน firmware ที่อ่านออกได้ โดยไม่ได้ตกลงกับเจ้าของ
- [ ] เจอความลับในโค้ดหรือประวัติ git ให้แจ้งเจ้าของทันที ความลับนั้นต้องเปลี่ยนใหม่ การลบออกจากไฟล์ไม่พอ

### ไฟล์อัปโหลด

- [ ] จำกัดขนาดและชนิด ตรวจชนิดจากเนื้อไฟล์ ไม่ใช่จากนามสกุลหรือ header
- [ ] ตั้งชื่อไฟล์ใหม่ฝั่ง server ไม่ใช้ชื่อจากผู้ใช้เป็น path
- [ ] เก็บนอกโฟลเดอร์ที่ server รันโค้ดได้ และเสิร์ฟด้วย content type ที่กำหนดเอง
- [ ] ตรวจสิทธิ์ทุกครั้งที่ดาวน์โหลด

### ระบบภายนอกและ webhook

- [ ] ตรวจลายเซ็นของ webhook ก่อนเชื่อเนื้อหา
- [ ] response จากระบบอื่นผ่าน schema เหมือน input อื่น
- [ ] มี timeout ทุกการเรียกออก และมีขีดจำกัดจำนวน retry
- [ ] ใช้ HTTPS และไม่ปิดการตรวจใบรับรอง

## ตัวอย่างช่องโหว่ที่พบบ่อย

เข้าถึงข้อมูลคนอื่นด้วยการเปลี่ยน id:

```ts
// ผิด: ใครล็อกอินก็ดูคำสั่งซื้อของทุกคนได้
const order = await orders.findById(params.order_id);
return order;

// ถูก: ตรวจความเป็นเจ้าของ
const order = await orders.findById(params.order_id);
if (order === null || order.order_user_id !== currentUserId) {
  throw new NotFoundError("ไม่พบคำสั่งซื้อ");
}
```

แก้ฟิลด์ที่ไม่ได้เปิดให้แก้:

```ts
// ผิด: ผู้ใช้ส่ง { user_role: "admin" } มาได้
await users.update(userId, request.body);

// ถูก: schema ระบุฟิลด์ที่แก้ได้ ฟิลด์อื่นถูกตัดทิ้ง
const input = UpdateProfileInputSchema.parse(request.body);
await users.updateProfile(userId, input);
```

เรียงด้วยชื่อคอลัมน์จากผู้ใช้:

```ts
// ถูก: แปลงค่าจากผู้ใช้เป็นคอลัมน์ผ่านรายการอนุญาต
const SORT_COLUMN = {
  created: "order_create_date",
  total: "order_total_satang",
} as const;
const SortSchema = z.enum(["created", "total"]).default("created");
```

## เมื่อเจอปัญหาความปลอดภัยนอกขอบเขตงาน

แจ้งเจ้าของพร้อมตำแหน่ง ผลกระทบ และวิธีแก้ที่เสนอ ไม่แก้เองนอกขอบเขต และไม่เขียนรายละเอียดวิธีโจมตีลงใน commit หรือที่สาธารณะ
