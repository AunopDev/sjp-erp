# รูปแบบหน้าจอ ส่วนประกอบ และค่าเริ่มต้น

ใช้คู่กับ [ux-ui.md](ux-ui.md) ไฟล์นั้นบอกขั้นตอนและหลักคิด ไฟล์นี้ให้ของที่หยิบใช้ได้ทันที ค่าทั้งหมดเป็นค่าเริ่มต้นสำหรับโปรเจ็กต์ที่ยังไม่มีระบบออกแบบ ถ้าโปรเจ็กต์มี token หรือ component library อยู่แล้ว ให้ใช้ของโปรเจ็กต์และใช้ไฟล์นี้เฉพาะส่วนที่ขาด

## สารบัญ

1. Design token เริ่มต้น
2. โครงหน้าจอตามชนิด
3. กฎของส่วนประกอบ
4. ข้อความบนหน้าจอ (microcopy)
5. ตัวอย่างสเปกหน้าจอครบชุด
6. โครง HTML สำหรับ mockup
7. Responsive ตามขนาดจอ
8. ตรวจความใช้ง่าย

## 1. Design token เริ่มต้น

```css
:root {
  /* สี: คู่ข้อความกับพื้นหลังด้านล่างผ่าน contrast 4.5:1 */
  --color-bg: #ffffff;
  --color-surface: #f5f5f5;
  --color-border: #d4d4d4;
  --color-text: #1a1a1a;
  --color-text-muted: #525252;
  --color-primary: #1d4ed8;
  --color-primary-hover: #1e40af;
  --color-on-primary: #ffffff;
  --color-danger: #b91c1c;
  --color-success: #15803d;
  --color-warning-bg: #fef3c7;
  --color-warning-text: #78350f;
  --color-focus: #2563eb;

  /* ระยะห่าง: ใช้เฉพาะค่าในชุดนี้ */
  --space-1: 4px;
  --space-2: 8px;
  --space-3: 12px;
  --space-4: 16px;
  --space-6: 24px;
  --space-8: 32px;
  --space-12: 48px;

  /* ตัวอักษร */
  --font-sans: "Noto Sans Thai", "Sarabun", system-ui, sans-serif;
  --text-sm: 14px;
  --text-base: 16px;
  --text-lg: 18px;
  --text-xl: 22px;
  --text-2xl: 28px;
  --leading-body: 1.6;
  --leading-heading: 1.35;
  --weight-normal: 400;
  --weight-medium: 500;
  --weight-bold: 700;

  /* รูปทรง */
  --radius-sm: 6px;
  --radius-md: 10px;
  --border-width: 1px;
  --control-height: 44px;
  --content-max-width: 1120px;
  --form-max-width: 560px;
}
```

กฎการใช้:

- ข้อความเนื้อหาไม่เล็กกว่า 16px บนมือถือ ข้อความรอง 14px
- หนึ่งหน้าจอใช้ขนาดตัวอักษรไม่เกิน 4 ขนาด และน้ำหนักไม่เกิน 2 ระดับ
- สีหลัก (`--color-primary`) ใช้กับปุ่มหลัก ลิงก์ และสถานะที่เลือกอยู่เท่านั้น ถ้าเจ้าของมีสีแบรนด์ให้แทนค่านี้ แล้วตรวจ contrast กับข้อความสีขาวใหม่
- ฟอนต์ต้องเป็นตัวที่โปรเจ็กต์โหลดได้จริง ถ้าไม่ได้โหลดฟอนต์เว็บ ให้ใช้ `system-ui` ซึ่งรองรับไทยในทุกระบบ
- Breakpoint เริ่มต้น: มือถือ < 640px, แท็บเล็ต 640–1023px, เดสก์ท็อป ≥ 1024px

## 2. โครงหน้าจอตามชนิด

เลือกชนิดที่ตรงกับจุดประสงค์ของหน้า แล้วใช้โครงนี้เป็นจุดเริ่ม

### รายการ (list)

จุดประสงค์: หาและเลือกรายการ

- บนสุด: ชื่อหน้า และปุ่มหลัก "เพิ่ม..." ชิดขวา
- ถัดมา: ค้นหา และตัวกรองที่ใช้บ่อยไม่เกิน 3 ตัว ตัวกรองที่เหลือซ่อนใน "ตัวกรองเพิ่มเติม"
- เนื้อหา: เดสก์ท็อปใช้ตาราง มือถือเปลี่ยนเป็นการ์ดเรียงลง แต่ละแถวแสดง 3–5 ข้อมูลที่ใช้ตัดสินใจ ไม่แสดงทุกคอลัมน์
- ล่าง: pagination หรือ "โหลดเพิ่ม" พร้อมจำนวนทั้งหมด
- ทั้งแถวกดได้เพื่อไปหน้ารายละเอียด การกระทำต่อแถวไม่เกิน 2 ปุ่ม ที่เหลือใส่เมนู
- ต้องมี: สถานะว่าง, ค้นหาไม่พบ (ต่างจากว่าง: บอกคำค้นและให้ปุ่มล้างตัวกรอง), โหลด, ผิดพลาด

### รายละเอียด (detail)

จุดประสงค์: ดูข้อมูลครบของหนึ่งรายการ และทำการกระทำกับมัน

- บนสุด: ทางกลับไปรายการ ชื่อรายการ ป้ายสถานะ
- ปุ่มการกระทำ: ปุ่มหลักหนึ่งปุ่มตามสถานะปัจจุบัน ปุ่มอันตรายแยกออกและใช้สีแดงแบบเส้นขอบ
- เนื้อหา: จัดกลุ่มข้อมูลเป็นหมวดมีหัวข้อ แสดงเป็นคู่ "ป้าย: ค่า" ค่าที่ว่างแสดง "—" ไม่ปล่อยว่าง
- ประวัติการเปลี่ยนแปลงอยู่ล่างสุดถ้ามี

### ฟอร์ม (create / edit)

จุดประสงค์: กรอกข้อมูลให้ผ่านในครั้งเดียว

- คอลัมน์เดียว กว้างไม่เกิน `--form-max-width` เรียงตามลำดับที่ผู้ใช้นึกถึงข้อมูล
- จัดกลุ่มช่องที่เกี่ยวกันด้วยหัวข้อย่อย เกิน 8–10 ช่องให้แบ่งเป็นขั้น พร้อมตัวบอกขั้น
- ปุ่มล่างสุด: ปุ่มหลัก "บันทึก..." และปุ่มรอง "ยกเลิก" ปุ่มหลักอยู่ตำแหน่งเดียวกันทุกฟอร์มในแอป
- ตรวจแต่ละช่องเมื่อออกจากช่อง และตรวจทั้งหมดเมื่อกดบันทึก เลื่อนไปช่องแรกที่ผิด
- ออกจากหน้าโดยมีข้อมูลที่ยังไม่บันทึก ให้ถามยืนยัน
- หน้าแก้ไขเติมค่าเดิมให้ และปุ่มบันทึกใช้ได้เมื่อมีการเปลี่ยนแปลง

### แดชบอร์ด

จุดประสงค์: เห็นสถานะรวมและรู้ว่าต้องทำอะไรต่อ

- แถวบน: ตัวเลขสำคัญ 3–4 ตัว แต่ละตัวมีป้าย ค่า และการเปลี่ยนแปลงเทียบช่วงก่อน
- ถัดมา: สิ่งที่ต้องทำหรือผิดปกติ (รายการรออนุมัติ, การแจ้งเตือน) อยู่เหนือกราฟ เพราะเป็นสิ่งที่นำไปสู่การกระทำ
- กราฟ 1–2 ตัวที่ตอบคำถามเฉพาะ มีชื่อที่บอกสิ่งที่แสดง และช่วงเวลาที่เลือกได้
- ทุกตัวเลขกดเข้าไปดูรายการที่มาได้

### เข้าสู่ระบบ / สมัคร

- กล่องเดียวกลางจอ: โลโก้หรือชื่อระบบ, ช่องกรอก, ปุ่มหลัก, ลิงก์ลืมรหัสผ่าน
- ช่องรหัสผ่านมีปุ่มแสดง/ซ่อน
- ข้อผิดพลาดการล็อกอินใช้ข้อความเดียว "อีเมลหรือรหัสผ่านไม่ถูกต้อง" ไม่บอกว่าช่องไหนผิด เพื่อไม่ให้เดาได้ว่ามีบัญชีอยู่

### ตั้งค่า

- จัดหมวดด้วยเมนูด้านข้าง (เดสก์ท็อป) หรือรายการที่กดเข้าไป (มือถือ)
- แต่ละการตั้งค่ามีป้าย คำอธิบายหนึ่งบรรทัดว่ามีผลอะไร และตัวควบคุม
- สวิตช์มีผลทันทีพร้อมการยืนยันสั้น ๆ ฟอร์มที่มีหลายช่องใช้ปุ่มบันทึก
- การกระทำอันตราย (ลบบัญชี) แยกไว้หมวดล่างสุด

## 3. กฎของส่วนประกอบ

| ส่วนประกอบ | กฎ |
| --- | --- |
| ปุ่ม | สามระดับ: หลัก (พื้นสีหลัก) หนึ่งปุ่มต่อหน้า, รอง (เส้นขอบ), ข้อความ (ไม่มีพื้น) สูง `--control-height` ขณะทำงานแสดงตัวหมุนและกดซ้ำไม่ได้ ปุ่ม disabled ต้องมีคำอธิบายว่าทำไมกดไม่ได้ |
| ช่องกรอก | label ด้านบน, ข้อความช่วยใต้ช่อง, ข้อผิดพลาดแทนที่ข้อความช่วยด้วยสีแดงพร้อมไอคอน สูง `--control-height` ขอบชัดเจน focus เห็นวงสี |
| ตัวเลือก | 2–5 ตัวเลือกใช้ radio แสดงทั้งหมด มากกว่านั้นใช้ select เกิน 15 ใช้ select ที่ค้นหาได้ ใช่/ไม่ใช่ที่มีผลทันทีใช้สวิตช์ |
| ตาราง | หัวตารางติดบนเมื่อเลื่อน ตัวเลขชิดขวา ข้อความชิดซ้าย คอลัมน์ที่เรียงได้มีเครื่องหมายบอก ข้อความยาวตัดด้วย ellipsis และดูเต็มได้ |
| Modal | ใช้เมื่อต้องการคำตอบก่อนทำต่อเท่านั้น มีหัวข้อ, เนื้อหาสั้น, ปุ่มไม่เกินสอง ปิดได้ด้วย Esc และปุ่มปิด focus อยู่ใน modal งานที่ซับซ้อนให้ใช้หน้าเต็มแทน |
| ยืนยันการลบ | หัวข้อเป็นคำถามที่ระบุชื่อสิ่งที่จะลบ เนื้อหาบอกผลที่ตามมา ปุ่มยืนยันเป็นสีแดงและเขียนกริยา "ลบรายการ" ปุ่มยกเลิกเป็นค่าเริ่มต้นที่ focus |
| Toast | ยืนยันผลสำเร็จของการกระทำที่ไม่เปลี่ยนหน้า แสดง 4–6 วินาที ข้อผิดพลาดที่ผู้ใช้ต้องแก้ไม่ใช้ toast ให้แสดงค้างใกล้จุดที่เกิด |
| ป้ายสถานะ | ข้อความสั้น + สี + ถ้าเป็นไปได้มีไอคอน ใช้ชื่อสถานะเดียวกันทุกหน้า |
| การนำทาง | เดสก์ท็อป: แถบด้านข้างหรือด้านบน มือถือ: แถบล่างไม่เกิน 5 รายการ รายการที่อยู่ปัจจุบันเน้นชัด ชื่อเมนูเป็นคำนามที่ผู้ใช้ใช้เรียก |
| Skeleton | รูปร่างใกล้เคียงเนื้อหาจริง ใช้เมื่อโหลดทั้งหน้าหรือทั้งส่วน การกระทำเล็ก ๆ ใช้ตัวหมุนในปุ่ม |

## 4. ข้อความบนหน้าจอ

ใช้ภาษาที่ผู้ใช้พูด สั้น และบอกสิ่งที่ทำต่อได้ เลือกสรรพนามและระดับภาษาแบบเดียวทั้งแอป

| สถานการณ์ | ไม่ดี | ดี |
| --- | --- | --- |
| ปุ่มบันทึก | ตกลง | บันทึกการแก้ไข |
| ปุ่มลบ | ยืนยัน | ลบรายการ |
| ช่องว่างที่บังคับ | ข้อมูลไม่ถูกต้อง | กรุณากรอกชื่อ |
| รูปแบบผิด | Invalid email | อีเมลไม่ถูกต้อง ตัวอย่าง: name@example.com |
| หน้าว่าง | ไม่มีข้อมูล | ยังไม่มีรายการตรวจ เริ่มด้วยการเพิ่มจุดตรวจแรก |
| ค้นหาไม่พบ | ไม่พบ | ไม่พบรายการที่ตรงกับ "..." ลองคำอื่นหรือล้างตัวกรอง |
| โหลดไม่สำเร็จ | Error 500 | โหลดรายการไม่สำเร็จ ตรวจการเชื่อมต่อแล้วลองใหม่ |
| สำเร็จ | Success | บันทึกแล้ว |
| ยืนยันการลบ | แน่ใจหรือไม่? | ลบ "จุดตรวจ A-01" หรือไม่ ประวัติการตรวจของจุดนี้จะถูกลบด้วยและกู้คืนไม่ได้ |
| ไม่มีสิทธิ์ | Forbidden | คุณไม่มีสิทธิ์ดูหน้านี้ ติดต่อผู้ดูแลระบบหากต้องการใช้งาน |

ข้อความผิดพลาดไม่โทษผู้ใช้ ไม่ใช้ศัพท์เทคนิคหรือรหัส error เป็นข้อความหลัก (ใส่รหัสอ้างอิงเล็ก ๆ ได้เพื่อแจ้งผู้ดูแล)

## 5. ตัวอย่างสเปกหน้าจอครบชุด

หน้า "รายการคำขอลาของฉัน" จาก flow ใน [system-design.md](system-design.md)

| หัวข้อ | รายละเอียด |
| --- | --- |
| จุดประสงค์ | พนักงานดูสถานะคำขอลาของตัวเอง และเริ่มสร้างคำขอใหม่ |
| ทางเข้า | เมนู "การลา", หลังส่งคำขอสำเร็จ |
| ทางออก | แตะแถว → รายละเอียดคำขอ, ปุ่ม "ขอลา" → ฟอร์มขอลา |
| การกระทำหลัก | "ขอลา" |
| การกระทำรอง | กรองตามสถานะ, ยกเลิกคำขอที่รออนุมัติ (ในหน้ารายละเอียด) |
| ข้อมูลที่แสดง | วันลาคงเหลือ (ด้านบน), ต่อแถว: ช่วงวันที่, จำนวนวัน, ประเภทการลา, ป้ายสถานะ เรียงจากใหม่ไปเก่า |
| ข้อมูลที่รับ | ตัวกรองสถานะ: ทั้งหมด / รออนุมัติ / อนุมัติแล้ว / ไม่อนุมัติ / ยกเลิก |
| สิทธิ์ | เห็นเฉพาะคำขอของตัวเอง |

| สถานะ | สิ่งที่แสดง |
| --- | --- |
| กำลังโหลด | skeleton ของวันลาคงเหลือและ 3 แถว |
| ว่าง | "ยังไม่มีคำขอลา" + ปุ่ม "ขอลา" |
| กรองแล้วไม่พบ | "ไม่มีคำขอในสถานะนี้" + ลิงก์ "ดูทั้งหมด" |
| มีข้อมูล | รายการ หน้าละ 20 พร้อม "โหลดเพิ่ม" |
| ผิดพลาด | "โหลดคำขอลาไม่สำเร็จ" + ปุ่ม "ลองใหม่" วันลาคงเหลือแสดง "—" |
| หลังส่งคำขอ | toast "ส่งคำขอลาแล้ว" และแถวใหม่อยู่บนสุดสถานะรออนุมัติ |

```text
└──────────────────────────────┘
เดสก์ท็อป: วันลาคงเหลือและปุ่ม "ขอลา" อยู่แถวเดียวกันด้านบน รายการเป็นตาราง
คอลัมน์: ช่วงวันที่ | จำนวนวัน | ประเภท | สถานะ
```

การตัดสินใจ: แสดงวันลาคงเหลือเหนือปุ่มขอลา เพราะเป็นข้อมูลที่ใช้ตัดสินใจก่อนกด ปุ่มยกเลิกไม่อยู่ในแถว เพราะเป็นการกระทำที่ทำไม่บ่อยและกดพลาดแล้วเสียหาย

## 7. Responsive ตามขนาดจอ

ทุกหน้าจอต้องใช้งานได้ครบที่ความกว้าง 360px ถึง 1440px ขึ้นไป โดยไม่มีแถบเลื่อนแนวนอนและไม่มีฟังก์ชันที่หายไปบนจอเล็ก เขียนสไตล์สำหรับจอเล็กเป็นค่าตั้งต้น แล้วเพิ่ม `@media (min-width: ...)` สำหรับจอที่กว้างขึ้น

| ส่วน | มือถือ < 640px | แท็บเล็ต 640–1023px | เดสก์ท็อป ≥ 1024px |
| --- | --- | --- | --- |
| การนำทาง | แถบล่างไม่เกิน 5 รายการ หรือเมนูที่กดเปิด | แถบด้านข้างแบบย่อ หรือแถบบน | แถบด้านข้างเต็ม หรือแถบบน |
| เนื้อหา | คอลัมน์เดียว ขอบ 16px | 1–2 คอลัมน์ ขอบ 24px | หลายคอลัมน์ กว้างสุด `--content-max-width` จัดกลาง |
| ตาราง | เปลี่ยนเป็นการ์ดเรียงลง แสดง 3–5 ข้อมูลหลัก | ตาราง ซ่อนคอลัมน์รอง | ตารางเต็ม |
| ฟอร์ม | ช่องเต็มความกว้าง เรียงลง | ช่องสั้นที่เกี่ยวกันวางคู่ได้ | คอลัมน์เดียวกว้างสุด `--form-max-width` ช่องสั้นวางคู่ได้ |
| ปุ่มหลัก | เต็มความกว้าง อยู่ล่างสุดหรือติดขอบล่าง | ขนาดตามเนื้อหา | ขนาดตามเนื้อหา |
| Modal | เต็มจอหรือแผ่นเลื่อนขึ้นจากล่าง | กล่องกลางจอ | กล่องกลางจอ |
| ตัวกรอง | ซ่อนในปุ่ม "ตัวกรอง" หรือแถบเลื่อนแนวนอน | แถวเดียวเหนือรายการ | แถวเดียวเหนือรายการ หรือแถบด้านข้าง |

กฎที่ใช้ทุกขนาด:

- ใช้ layout ที่ยืดหยุ่น (flex, grid, `minmax`, `%`, `rem`) ไม่กำหนดความกว้างตายตัวเป็น px ให้กล่องเนื้อหา
- รูปและสื่อ: `max-width: 100%` และ `height: auto`
- ข้อความยาวต้องตัดบรรทัดหรือย่อด้วย ellipsis ไม่ดันกล่องให้ล้น ทดสอบด้วยข้อความไทยยาว ๆ
- เป้ากดอย่างน้อย 44×44px ทุกขนาดจอ เพราะแท็บเล็ตและโน้ตบุ๊กจอสัมผัสมีอยู่จริง
- ไม่พึ่ง hover อย่างเดียว สิ่งที่เห็นเมื่อ hover ต้องเข้าถึงได้ด้วยการแตะหรือ focus
- ไม่ปิดการซูมของผู้ใช้ และช่องกรอกใช้ตัวอักษรไม่เล็กกว่า 16px เพื่อไม่ให้มือถือซูมเองตอนพิมพ์
- ส่วนที่ติดขอบจอ (แถบบน, ปุ่มติดล่าง) ต้องไม่บังเนื้อหาและไม่บังช่องที่กำลังพิมพ์เมื่อคีย์บอร์ดขึ้น
- ซ่อนของบนจอเล็กได้เฉพาะสิ่งตกแต่งหรือข้อมูลรอง การกระทำทุกอย่างต้องยังทำได้

ตัวอย่างรายการที่เป็นการ์ดบนมือถือและตารางบนจอใหญ่:

```css
.record-list { display: grid; gap: var(--space-3); }
.record {
  display: grid;
  gap: var(--space-1);
  padding: var(--space-4);
  border: var(--border-width) solid var(--color-border);
  border-radius: var(--radius-md);
}
@media (min-width: 1024px) {
  .record-list { gap: 0; }
  .record {
    grid-template-columns: 2fr 1fr 1fr auto;
    align-items: center;
    gap: var(--space-4);
    border-width: 0 0 var(--border-width) 0;
    border-radius: 0;
  }
}
```

ตรวจที่ความกว้าง 360, 768, 1024 และ 1440px ถ้าเปิดดูจริงไม่ได้ ให้ไล่อ่าน CSS ทีละ breakpoint และระบุในรายงานว่ายังไม่ได้ดูบนจอจริง

## 8. ตรวจความใช้ง่าย

ไล่ทีละข้อโดยสมมติว่าเป็นผู้ใช้ที่เปิดหน้านี้ครั้งแรก ข้อที่ตอบว่าไม่ ให้แก้ก่อนส่ง

- [ ] **รู้ว่าอยู่ที่ไหน:** มีชื่อหน้า และเมนูเน้นตำแหน่งปัจจุบัน
- [ ] **รู้ว่าต้องทำอะไร:** ภายในห้าวินาทีบอกได้ว่าหน้านี้ทำอะไรและปุ่มหลักคือปุ่มไหน
- [ ] **ขั้นตอนน้อยที่สุด:** งานที่ทำบ่อยเสร็จได้ในไม่กี่การกด ไม่มีขั้นที่ตัดออกได้
- [ ] **ไม่ต้องจำ:** ข้อมูลที่ต้องใช้ตัดสินใจอยู่บนหน้าเดียวกัน ไม่ต้องจำจากหน้าก่อน
- [ ] **ช่วยกรอก:** มีค่าเริ่มต้นที่สมเหตุสมผล เติมอัตโนมัติจากข้อมูลที่ระบบรู้ และบอกรูปแบบที่ต้องการก่อนพิมพ์
- [ ] **กันพลาด:** ปิดหรืออธิบายตัวเลือกที่ใช้ไม่ได้ ยืนยันก่อนการกระทำที่ย้อนไม่ได้ หรือมี undo
- [ ] **บอกผลทุกครั้ง:** ทุกการกดมีการตอบสนองทันที และบอกชัดว่าสำเร็จหรือไม่
- [ ] **แก้ข้อผิดพลาดได้เอง:** ข้อความบอกว่าเกิดอะไรและต้องทำอะไรต่อ ข้อมูลที่กรอกไว้ไม่หาย
- [ ] **ภาษาของผู้ใช้:** ใช้คำที่ผู้ใช้เรียกจริง ไม่มีศัพท์ของระบบหรือชื่อฟิลด์ในฐานข้อมูล
- [ ] **สม่ำเสมอ:** ของชนิดเดียวกันอยู่ตำแหน่งเดียวกันและหน้าตาเดียวกันทุกหน้า
- [ ] **ย้อนกลับได้:** มีทางกลับหรือยกเลิกจากทุกหน้าและทุกกล่องโต้ตอบ
- [ ] **ใช้มือเดียวบนมือถือได้:** การกระทำหลักอยู่ในระยะนิ้วโป้ง ไม่ต้องพิมพ์ในสิ่งที่เลือกได้
- [ ] **ไม่รก:** ทุกองค์ประกอบบนหน้ามีเหตุผลที่อยู่ตรงนั้น สิ่งที่ใช้นาน ๆ ครั้งซ่อนไว้หลังเมนู
