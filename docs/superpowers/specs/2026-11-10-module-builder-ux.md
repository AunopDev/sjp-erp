## 1. ปัญหาก่อนปรับ

- เลือกโมดูลจาก dropdown ยาว ๆ หาโมดูลยาก
- ฟอร์มตั้งค่าและตารางฟิลด์อยู่ในหน้าเดียว ยาวและหนัก
- ตารางฟิลด์มี input/select หลายชิ้นต่อแถว อ่านยาก
- ปุ่มบันทึกอยู่ล่างสุดของหน้า
- ไม่รู้ว่ากำลังแก้โมดูลไหน แก้แล้วยังไม่บันทึกหรือไม่
- โมดูลระบบเปิดแก้ได้ แต่บันทึกไม่ผ่าน ทำให้สับสน
- การเปลี่ยน key ถูกซ่อนอยู่ในตาราง

## 2. โครงสร้างใหม่

### 2.1 Module browser ด้านซ้าย
- ช่องค้นหาโมดูล (ชื่อ / key / prefix)
- แบ่งกลุ่ม **แก้ไขได้** และ **โมดูลระบบ**
- แต่ละรายการแสดงไอคอน, ชื่อ, prefix, จำนวนฟิลด์, tag สร้างเอง/ระบบ
- คลิกเพื่อสลับโมดูล
- ปุ่มสร้างโมดูล/นำเข้า JSON อยู่ในบริเวณนี้

### 2.2 Editor ด้านขวา
- Header: ไอคอน, ชื่อโมดูล, prefix, จำนวนฟิลด์, ประเภท
- ปุ่มทำสำเนา/ส่งออก/ลบ สำหรับโมดูลที่สร้างเอง
- Tabs 3 ส่วน:
  1. **ข้อมูลโมดูล** — ชื่อ, ชื่อเมนูสั้น, prefix, ฟิลด์ชื่อรายการ, หมวดเมนู, ไอคอน, คำอธิบาย, scope
  2. **ฟิลด์** — รายการฟิลด์ + เพิ่ม/แก้ไข/จัดลำดับ
  3. **มุมมองรายการ** — คอลัมน์และตัวกรอง
- Role access และตัวเลือกกลาง (ทีม/แผนก) อยู่ในแท็บข้อมูลโมดูล

### 2.3 Field list แบบอ่านง่าย
- แต่ละแถวแสดง:
  - ลำดับ + drag + ปุ่มขึ้น/ลง
  - ชื่อฟิลด์ + key
  - ชนิด + flag สำคัญ (บังคับ/ซ่อน/ห้ามซ้ำ/อ่านอย่างเดียว)
  - สรุปตัวเลือก/การเชื่อม/จำนวนคอลัมน์
  - ปุ่มแก้ไข/ลบ
- การเพิ่ม/แก้ไขฟิลด์ทำใน modal เดียว
- Modal รองรับ help, suffix, ตัวเลือก, ref, flags ครบ
- ปุ่ม **เปลี่ยน key** อยู่ใน modal (พร้อมคำเตือนเรื่องการย้ายข้อมูล)

### 2.4 Save & safety
- Save bar sticky ด้านล่าง แสดง
  - ข้อความ “มีการแก้ไขที่ยังไม่บันทึก”
  - error จาก server
  - ปุ่มบันทึกโครงสร้าง
- ถ้าเปลี่ยนโมดูลขณะมีแก้ไข จะถามยืนยันก่อนทิ้ง
- โมดูลระบบถูกทำเป็น read-only:
  - แบนเนอร์แจ้ง
  - fieldset ถูก disable
  - ไม่มีปุ่มเพิ่มฟิลด์/บันทึก
  - แสดง badge “อ่านอย่างเดียว”

## 3. Responsive

| Width | พฤติกรรม |
|---|---|
| >1200 | Module list เป็นคอลัมน์ซ้าย sticky, editor อยู่ขวา |
| 701–1200 | Module list เป็นแถวแนวนอน เลื่อนซ้าย–ขวา, editor อยู่ด้านล่าง |
| <=700 | Module list เป็นการ์ดแนวนอน, field list เปลี่ยนเป็น layout 3 คอลัมน์ (ลำดับ / เนื้อหา / ปุ่ม) |
| <=900 | Save bar ลอยเหนือ bottom navigation |

Field row บนมือถือ: type + flags รวมเป็นกลุ่มเดียว ไม่แตกเป็นหลายบรรทัด

## 4. สิ่งที่ตรวจแล้ว

- สร้างโมดูลใหม่จาก UI สำเร็จ
- เพิ่มฟิลด์ + บันทึกโครงสร้างสำเร็จ
- dirty indicator ทำงาน
- เปลี่ยนโมดูลขณะ dirty → confirm
- โมดูลระบบแสดง read-only ถูกต้อง
- เปลี่ยน key เปิด modal ได้
- จัดลำดับฟิลด์ด้วยปุ่มขึ้น/ลงได้
- tabs ข้อมูลโมดูล/ฟิลด์/มุมมองรายการทำงาน
- build ผ่าน, tests 10/10
- ตรวจ layout 1440 / 1024 / 390 + dark mode
