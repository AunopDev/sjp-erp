## 1. เป้าหมาย

ให้พนักงานตรวจได้ว่าช่วงใดรถว่าง แล้วจองได้ทันที โดยไม่ต้องสร้างตารางฐานข้อมูลใหม่
และยังคงใช้ metadata JSON, permission model และ audit/event เดิมของระบบ

## 2. โมเดลข้อมูล

เพิ่ม entity ระบบ 2 ตัวใน `server/src/meta/entities.ts` (เก็บเป็น `records` JSON):

### `vehicles` — รถบริษัท

| ฟิลด์ | ชนิด | หมายเหตุ |
|---|---|---|
| name | text | ชื่อรถ/รุ่น |
| plateNo | text | ทะเบียนรถ, ห้ามซ้ำ |
| type | select | รถเก๋ง / รถกระบะ / รถตู้ / อื่นๆ |
| seats | number | จำนวนที่นั่ง |
| driver | ref users | พนักงานขับประจำ |
| status | select | พร้อมใช้ / ซ่อมบำรุง / ไม่พร้อมใช้ |
| note | textarea | หมายเหตุ |

### `vehicleBookings` — การจอง

| ฟิลด์ | ชนิด | หมายเหตุ |
|---|---|---|
| title | text | วัตถุประสงค์การเดินทาง |
| vehicle | ref vehicles | รถที่จอง |
| requester | text | ผู้จอง (เติมชื่อผู้ใช้ให้อัตโนมัติ) |
| department | text | แผนก |
| destination | text | ปลายทาง |
| startAt / endAt | datetime | เก็บเป็น ISO |
| passengers | number | จำนวนผู้โดยสาร |
| driver | ref users | พนักงานขับรถ |
| status | select | รออนุมัติ / อนุมัติแล้ว / ไม่อนุมัติ / ยกเลิก / เสร็จสิ้น |
| note | textarea | รายละเอียด + เหตุผลการไม่อนุมัติ |

ทั้งสอง entity ตั้ง `system: true` เพื่อล็อกโครงสร้างไม่ให้แก้ผ่าน Module Builder
แต่เปิด CRUD ระดับ record ผ่าน `SYSTEM_RECORD_CRUD` ใน `records.service.ts`

## 3. กติกาการจอง

ตรวจที่ `RecordsService.validateBusiness` ทั้งตอนสร้างและแก้ไข:

1. `endAt` ต้องมากกว่า `startAt`
2. รถต้องมีสถานะ `พร้อมใช้`
3. ห้ามช่วงเวลาทับซ้อนกับรถคันเดียวกัน
   - ตรวจเฉพาะรายการที่ไม่ใช่ `ยกเลิก` / `ไม่อนุมัติ`
   - เงื่อนไข overlap: `otherStart < end && otherEnd > start`
4. ข้อความ error ระบุเลขที่การจองที่ชน เช่น
   `ช่วงเวลานี้รถถูกจองแล้ว (VBK-0002)`

## 4. หน้า `/vehicles`

### 4.0 หารถว่าง (Quick finder) — ทางเข้าหลัก
- เลือกเวลาเริ่ม/สิ้นสุด, จำนวนผู้โดยสาร, ประเภทรถ
- ระบบกรองเฉพาะรถที่ **พร้อมใช้ + ว่างจริง** ในช่วงเวลานั้น
- แสดงการ์ดรถว่างพร้อมปุ่ม `จองคันนี้` (เติมรถ/วันเวลาให้ฟอร์มอัตโนมัติ)
- ค่าเริ่มต้น:
  - วันนี้ → ชั่วโมงถัดไป 2 ชั่วโมง (ไม่เกิน 21:00)
  - วันอื่น → 09:00–11:00
- ตรวจเวลาให้บริการ 06:00–21:00 และเตือนถ้าเลือกเวลาที่ผ่านมาแล้ว
- ถ้าไม่มีรถว่าง มีปุ่ม `ดูตารางการใช้รถ` และ `ล้างตัวกรอง`
- เนื้อหาหลักแบ่งเป็นแท็บ `รายการจอง` และ `ตารางการใช้รถ` เพื่อลดความรก

### 4.1 สรุปด้านบน
- รถทั้งหมด / พร้อมใช้
- รถว่างทั้งวัน (ไม่มีคิวจองในวันที่เลือก)
- จำนวนการจองในวันที่เลือก
- จำนวนรออนุมัติ

### 4.2 แถบสัปดาห์
- แสดง 7 วันของสัปดาห์ที่เลือก (จ.–อา.)
- แต่ละวันบอกจำนวนคิวจองที่ยัง active
- คลิกเพื่อเปลี่ยนวัน, วันนี้มีสีแดง, วันที่เลือกมีพื้นหลังแบรนด์

### 4.3 ตารางรถว่างรายชั่วโมง
- แถว = รถแต่ละคัน, คอลัมน์ = 06:00–21:00
- ช่องว่างคลิกเพื่อสร้างการจอง โดยเติมรถ/วันเวลาให้อัตโนมัติ
- ช่องที่มีการจองแสดงช่วงเวลา + สีตามสถานะ
- รถที่ไม่พร้อมใช้ถูกปิดทุกช่อง
- ช่องของ "ชั่วโมงปัจจุบัน" ถูกไฮไลต์
- ตารางเลื่อนแนวนอนได้บนมือถือ

### 4.4 รายการจอง
- ค้นหาจากวัตถุประสงค์ ผู้จอง ปลายทาง แผนก ทะเบียนรถ
- กรองตามสถานะ
- เฉพาะของฉัน (เทียบชื่อผู้จองกับผู้ใช้ปัจจุบัน)
- ส่งออก CSV ตามตัวกรอง
- สถานะที่คำนวณสด:
  - `กำลังใช้งาน` — อนุมัติแล้วและเวลาปัจจุบันอยู่ในช่วง
  - `เลยเวลาคืน` — อนุมัติแล้วและเลยเวลาสิ้นสุด
  - สถานะจริงอื่นๆ ตามที่บันทึก

### 4.5 การอนุมัติ
- ปุ่ม `อนุมัติ` / `ไม่อนุมัติ` แสดงเมื่อผู้ใช้มีสิทธิ์ `approve`
- ไม่อนุมัติสามารถใส่เหตุผลได้ ระบบต่อท้ายใน `note`
- อนุมัติแล้วจึงเข้าสู่สถานะใช้งานได้
- `เสร็จสิ้น` และ `ยกเลิก` ใช้สิทธิ์ `edit`
- รายการ `รออนุมัติ` ถูกส่งเข้ากระดิ่งแจ้งเตือนสำหรับผู้อนุมัติ พร้อมลิงก์กลับมาที่การจองนั้น

### 4.6 ข้อมูลรถ
- แสดงสถานะรถ, จำนวนที่นั่ง
- แสดง "ถูกจองถึง HH:mm" หรือ "ว่างตอนนี้"
- เพิ่ม/แก้ไขรถได้ตามสิทธิ์ `vehicles`

## 5. API

| Method | Path | สิทธิ์ |
|---|---|---|
| GET | `/api/records/vehicles` | vehicles.view |
| POST/PATCH | `/api/records/vehicles` | vehicles.create/edit |
| GET | `/api/records/vehicleBookings` | vehicleBookings.view |
| POST/PATCH | `/api/records/vehicleBookings` | vehicleBookings.create/edit |
| POST | `/api/records/vehicleBookings/:id/decision` | vehicleBookings.approve |
| GET | `/api/calendar` | vehicleBookings.view |

`decision` body:

```json
{ "decision": "approve" | "reject", "note": "เหตุผล (ไม่บังคับ)" }
```

## 6. ปฏิทิน

`CalendarService` สร้าง event ชนิด `vehicle`:
- วันที่/เวลาอ้างอิง timezone ธุรกิจ (`APP_TIMEZONE`, ค่าเริ่มต้น `Asia/Bangkok`) ไม่ใช่ UTC
- ข้ามรายการ `ยกเลิก` / `ไม่อนุมัติ`
- subtitle = รถ · ผู้จอง
- link = `/vehicles?date=YYYY-MM-DD&booking=<id>`

หน้า `/vehicles` อ่าน query `date`, `booking`, `new` เพื่อเปิดฟอร์มที่ถูกต้อง

## 7. สิทธิ์เริ่มต้น

| บทบาท | vehicles | vehicleBookings |
|---|---|---|
| admin | ทั้งหมด | ทั้งหมด |
| pm | view | view, create, edit, approve |
| helpdesk / tech / store / buyer | view (store: create/edit) | view, create, edit |
| exec | view | view, approve |

- role ที่มีอยู่เดิมถูก backfill เฉพาะ resource/action ใหม่
- Role Editor จัดกลุ่ม "ยานพาหนะ" และมี preset ทีมบริการ/ผู้จัดการรองรับ

## 8. สิ่งที่ตรวจแล้ว

- สร้างรถผ่าน UI และ API ได้
- คลิกช่องว่างเพื่อจองพร้อมค่าเริ่มต้นถูกต้อง
- จองทับช่วงเวลา → 400 พร้อมเลขที่การจองที่ชน
- จองรถสถานะซ่อมบำรุง → 400
- เวลาสิ้นสุดก่อนเวลาเริ่ม → 400
- ยกเลิกแล้วจึงจองช่วงเดิมซ้ำได้
- อนุมัติ/ไม่อนุมัติผ่าน API และผ่านปุ่ม UI
- กระดิ่งแจ้งเตือนผู้อนุมัติแสดงรายการจองรถพร้อมลิงก์
- เสร็จสิ้น/ยกเลิกผ่าน UI
- ค้นหา/กรองสถานะ/เฉพาะของฉันทำงาน
- ปฏิทินแสดง event ชนิด vehicle พร้อมลิงก์กลับหน้า `/vehicles`
- responsive 1440 / 390 และ dark mode

## 9. ไอเดียต่อยอด

- แจ้งเตือนผู้อนุมัติผ่านกระดิ่ง/อีเมล
- มอบหมายพนักงานขับอัตโนมัติตามรถ
- บันทึกเลขไมล์/น้ำมันก่อน–หลังใช้
- จองแบบซ้ำ (recurring) และจองหลายวัน
- แนบรูปสภาพรถก่อน–หลังใช้งาน
- ปฏิทินรายสัปดาห์ของรถแต่ละคัน
